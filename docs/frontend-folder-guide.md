# 프론트엔드 폴더 역할 가이드

이 문서는 현재 프론트엔드 코드가 사용하는 `src` 구조를 기준으로 각 폴더와 파일의 역할, 배치 기준을 정리한 문서다. 새로운 기능을 추가하거나 기존 코드를 정리할 때 이 가이드를 기준으로 경로를 결정한다.

## 1. 전체 구조

현재 프론트엔드는 하나의 실행 앱으로 구성되어 있으며, 모든 실행 코드와 화면 코드는 `src` 아래에 둔다.

```text
src/
├── assets/              # 화면에서 사용하는 이미지 및 정적 자산
│   ├── JobSearch/
│   ├── login/
│   └── main/
├── components/          # 여러 화면에서 재사용하는 UI 컴포넌트
├── layouts/             # 여러 화면에서 재사용하는 레이아웃
├── pages/               # 화면(페이지) 단위 기능
│   ├── JobSearch/
│   ├── Join/
│   ├── Login/
│   ├── Main/
│   │   └── sections/    # Main 화면 내부 섹션
│   ├── MyPage/
│   ├── TalentSearch/
│   └── index.ts
├── styles/              # 전역 및 공통 스타일
├── App.tsx              # 애플리케이션 최상위 컴포넌트
└── main.tsx             # 애플리케이션 시작점
```

## 2. 기본 원칙

- 실행 코드, 화면 코드, 스타일, 자산은 `src` 아래에서 관리한다.
- 화면 단위 코드는 `src/pages` 아래에 둔다.
- 특정 화면에서만 사용하는 컴포넌트와 스타일은 해당 페이지 폴더 안에 둔다.
- 두 개 이상의 화면에서 실제로 재사용되는 UI만 `src/components`로 옮긴다.
- 여러 화면에서 공통으로 사용하는 화면 골격만 `src/layouts`에 둔다.
- 화면 전용 이미지는 해당 화면을 식별할 수 있는 이름의 `src/assets` 하위 폴더에 둔다.
- 처음부터 공통 폴더에 넣기보다, 재사용이 확인된 뒤 공통화한다.
- 기존 폴더 구조와 import 경로를 불필요하게 바꾸지 않는다. 구조 변경이 필요하면 관련 import와 실행 여부를 함께 확인한다.

## 3. 폴더 및 파일별 역할

### `src/`

프론트엔드 애플리케이션의 소스 코드 루트다. 실행에 필요한 컴포넌트, 페이지, 스타일, 자산을 모두 이곳에서 관리한다.

### `src/main.tsx`

애플리케이션 시작점이다. 브라우저에서 최상위 React 앱을 마운트하는 코드처럼 앱 실행에 직접 필요한 초기화 코드를 둔다.

화면 구현이나 페이지별 UI를 이 파일에 작성하지 않는다.

### `src/App.tsx`

애플리케이션의 최상위 컴포넌트다. 전체 화면 구조, 페이지 진입 구조, 전역 수준의 설정처럼 앱 전체를 조합하는 역할을 둔다.

특정 페이지의 상세 UI는 `src/pages`에 작성한다.

### `src/pages/`

사용자가 직접 진입하는 화면 단위 코드를 둔다. 현재는 다음 화면 폴더가 있다.

| 폴더 | 역할 |
|---|---|
| `JobSearch/` | 공고를 탐색하는 화면 |
| `Join/` | 회원가입 화면 |
| `Login/` | 로그인 화면 |
| `Main/` | 메인 화면 |
| `MyPage/` | 마이페이지 화면 |
| `TalentSearch/` | 인재를 탐색하는 화면 |

페이지 폴더 이름은 화면의 업무 목적을 나타내는 `PascalCase`를 사용한다. 페이지의 대표 컴포넌트는 기본적으로 폴더 이름과 같은 이름의 `.tsx` 파일에 둔다.

예시:

```text
src/pages/Login/Login.tsx
src/pages/Join/Join.tsx
src/pages/JobSearch/JobSearch.tsx
```

페이지 하나에서만 사용하는 하위 컴포넌트, 섹션, 스타일은 해당 페이지 폴더 안에서 관리한다.

### `src/pages/Main/sections/`

`Main` 화면처럼 한 페이지가 여러 개의 시각적·기능적 영역으로 구성될 때, 페이지 내부 섹션을 분리해 둔다.

현재는 다음과 같이 구성되어 있다.

```text
src/pages/Main/Main.tsx
src/pages/Main/sections/Main1.tsx
src/pages/Main/sections/Main2.tsx
src/pages/Main/sections/Main3.tsx
src/pages/Main/sections/Main4.tsx
src/pages/Main/sections/Main5.tsx
```

섹션은 `Main` 화면 안에서만 사용되는 코드를 두는 곳이다. 다른 페이지에서도 같은 UI가 필요해지면 재사용 범위를 확인한 뒤 `src/components`로 이동한다.

### `src/pages/index.ts`

페이지 관련 모듈을 한 곳에서 내보내기 위한 진입 파일이다. 페이지 import가 여러 곳에 흩어져 관리하기 어려워질 때 export 목록을 정리하는 용도로 사용한다.

### `src/components/`

두 개 이상의 페이지에서 재사용되는 UI 컴포넌트를 둔다. 예를 들면 버튼, 입력창, 카드, 모달, 배지처럼 특정 업무 화면에 종속되지 않는 UI가 해당된다.

다음 코드는 이 폴더에 바로 넣지 않는다.

- 한 페이지에서만 사용하는 컴포넌트
- 특정 페이지의 업무 규칙에 강하게 종속된 컴포넌트
- 아직 재사용 여부가 확인되지 않은 컴포넌트

페이지 전용 컴포넌트는 해당 `pages/*` 폴더에 먼저 둔다.

### `src/layouts/`

여러 페이지에서 공유하는 화면 골격을 둔다. 예를 들면 공통 헤더, 푸터, 전체 페이지 컨테이너, 인증 여부에 따른 공통 레이아웃 등이 해당될 수 있다.

단순히 화면 안에서 한 번 사용되는 wrapper나 섹션은 `layouts`가 아니라 해당 페이지에 둔다.

### `src/styles/`

여러 페이지 또는 앱 전체에서 적용되는 전역·공통 스타일을 둔다.

- 전역 reset 및 기본 스타일
- 공통 색상, 글꼴, 간격 등 디자인 토큰
- 여러 화면에서 공유하는 스타일

특정 페이지에만 필요한 스타일은 해당 페이지 폴더에 둔다. 현재 `Login` 화면은 `src/pages/Login/login.css`처럼 페이지 옆에 화면 전용 스타일을 두고 있다.

### `src/assets/`

코드에서 import해 사용하는 이미지와 정적 자산을 둔다. 자산은 가능한 한 사용하는 화면별로 하위 폴더를 나눈다.

현재 구성:

```text
src/assets/JobSearch/     # JobSearch 화면용 자산 폴더
src/assets/login/         # Login 화면용 자산
  login.png
src/assets/main/          # Main 화면용 자산
  image 1.png ~ image 6.png
```

자산을 추가할 때는 다음 기준을 따른다.

- 한 화면에서만 사용하면 해당 화면 폴더에 둔다.
- 여러 화면에서 사용하는 공통 자산이면 `assets` 아래 공통 목적을 나타내는 폴더에 둔다.
- 파일명은 역할을 알 수 있게 작성하고, 가능하면 공백 대신 `kebab-case` 또는 `camelCase`를 사용한다.
- 사용하지 않는 자산을 임의로 공통 폴더에 복사하지 않는다.

## 4. 파일 배치 판단 기준

새 파일을 만들 때는 아래 순서로 판단한다.

1. 앱 실행과 최상위 조합에 필요한가? → `src/main.tsx` 또는 `src/App.tsx`
2. 사용자가 진입하는 하나의 화면인가? → `src/pages/<PageName>/`
3. 페이지 내부에서만 사용하는가? → 해당 페이지 폴더
4. 두 개 이상의 페이지에서 재사용되는 UI인가? → `src/components/`
5. 여러 페이지의 화면 골격인가? → `src/layouts/`
6. 여러 화면에 적용되는 스타일인가? → `src/styles/`
7. 이미지나 정적 자산인가? → `src/assets/` 아래 사용 범위에 맞는 폴더

업무 흐름이나 API 호출처럼 별도의 역할이 생길 때는 현재 구조와 기술 스택을 확인한 뒤 별도 폴더를 추가한다. 새로운 최상위 폴더는 필요성과 사용 범위를 먼저 합의하고 만든다.

## 5. 현재 구현 상태

- `main.tsx`, `App.tsx`와 일부 페이지 컴포넌트가 구현되어 있다.
- `pages`에는 `JobSearch`, `Join`, `Login`, `Main`, `MyPage`, `TalentSearch` 화면이 준비되어 있다.
- `Main`은 `sections` 하위 컴포넌트로 화면을 나누고 있다.
- `Login`에는 페이지 전용 CSS 파일이 있다.
- `assets`에는 로그인 및 메인 화면 이미지가 있으며, `JobSearch` 자산 폴더도 준비되어 있다.
- `components`, `layouts`, `styles`는 공통 코드가 필요해질 때 사용할 수 있도록 준비된 폴더다.

이 문서는 현재 구조를 설명하는 동시에 이후 확장을 위한 기준이다. 새로운 프레임워크, 라우팅, 상태관리, API 계층을 도입할 때는 기존 `src` 구조와의 관계를 먼저 정리한 후 문서를 함께 갱신한다.
