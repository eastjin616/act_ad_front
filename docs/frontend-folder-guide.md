# 프론트엔드 폴더 역할 가이드

현재 저장소는 구현 전 폴더 스켈레톤만 준비한 상태다. 이 문서는 팀원이 각 폴더에 어떤 종류의 파일을 둘지 맞추기 위한 기준이다.

## 기본 원칙

- `apps/`에는 실제로 실행되는 화면 단위 앱을 둔다.
- `common/`에는 여러 앱에서 함께 쓰는 공통 코드를 둔다.
- 앱별로만 필요한 코드는 해당 `apps/*` 안에 둔다.
- 두 앱 이상에서 반복될 코드만 `common/*`로 옮긴다.
- 프레임워크, 라우팅, 상태관리, 패키지 매니저는 별도 기획 후 확정한다.

## 폴더별 역할

| 폴더 | 역할 | 들어갈 수 있는 것 | 아직 하지 않을 것 |
|---|---|---|---|
| `apps/miniapp/` | 앱 사용자를 위한 모바일/미니앱 프론트 | 공고 탐색, 공고 상세, 지원, 프로필 등록 화면 | 프레임워크 초기화, 네이티브 프로젝트 생성 |
| `apps/web/` | 관리자 웹 프론트 | 프로젝트 등록, 공고 관리, 지원자 관리, 프리프로덕션 관리 화면 | 관리자 라우팅/권한 구조 확정 없이 구현 시작 |
| `common/ui/` | 공통 UI 컴포넌트 | 버튼, 입력창, 카드, 모달, 배지, 레이아웃 컴포넌트 | 특정 화면에만 쓰이는 UI를 섣불리 공통화 |
| `common/features/` | 공통 기능 단위 | 공고 목록, 프로젝트 상세, 지원 흐름, 프로필/경력 입력 흐름 | 앱별 화면 전체를 그대로 이동 |
| `common/api-client/` | 백엔드 API 호출 공통 코드 | API client, 요청/응답 처리, 인증 토큰 연결, 에러 처리 | 백엔드 계약 확정 전 임의 API 스키마 작성 |
| `common/types/` | 앱 전체에서 공유하는 타입 | 프로젝트, 공고, 사용자, 지원자, 프로필, 경력 타입 | 한 화면에서만 쓰는 임시 타입 남발 |

## 판단 기준

어떤 파일을 어디에 둘지 애매하면 아래 순서로 판단한다.

1. 한 앱에서만 쓰면 `apps/*`에 둔다.
2. 두 앱 이상에서 같은 의미로 쓰면 `common/*`에 둔다.
3. UI 모양만 공통이면 `common/ui/`에 둔다.
4. 업무 흐름이나 도메인 로직이 공통이면 `common/features/`에 둔다.
5. 서버 통신이면 `common/api-client/`에 둔다.
6. 데이터 구조나 타입 이름이면 `common/types/`에 둔다.

## 현재 상태

- 각 폴더에는 Git 추적용 `.gitkeep`만 있다.
- 실제 React Native, Next.js, npm, build 설정은 아직 없다.
- 구현은 팀원 간 기획과 기술 선택을 확정한 뒤 시작한다.
