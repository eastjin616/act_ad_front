# 프론트엔드 채널 구조 구체화

## 배경

초기 README는 `act_ad_front`를 앱인토스 미니앱 전용 프론트엔드로 설명했다. 하지만 배우, 스태프, 엔터테인먼트 회사 및 제작사는 앱인토스 미니앱뿐 아니라 일반 웹에서도 서비스를 사용할 수 있어야 한다.

## 구현 방식

- `act_ad_front`를 프론트엔드 모노레포로 정의했다.
- 앱인토스 WebView 미니앱은 `apps/miniapp/`, 일반 웹 서비스는 `apps/web/`으로 분리할 계획을 기록했다.
- UI, 공고·프로필·지원 기능, API 호출, 타입은 `packages/`에서 공유하도록 구조를 정리했다.
- 핵심 기능은 두 채널에서 모두 제공하고, 제작사 관리와 프리프로덕션 기능의 상세 수준만 채널에 따라 다르게 구성했다.

## 핵심 결정

- 일반 웹은 제작사 관리자 전용 화면이 아니다.
- 배우, 스태프, 제작사 모두 일반 웹과 앱인토스 미니앱에서 핵심 기능을 사용할 수 있다.
- 두 채널은 같은 백엔드 API를 사용한다.
- 프론트엔드 저장소는 채널별로 분리하지 않고 하나의 모노레포로 유지한다.

- 채널별 인증 흐름을 설계해야 한다.
